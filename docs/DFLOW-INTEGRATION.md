# Active execution and measurement procedure

This is the on-demand guide for the active Delivery Flow update of 2026-10-29.
`DELIVERY-FLOW.md`, `REVIEWING.md` and `TOKEN-BUDGET.md` remain the rules. The
machine's local profile supplies installed paths and interfaces. This procedure
uses delivered tools and native host operations; it does not claim that the
proposed dflow execution engine has been built.

## Discovery and resume

Read current shared instructions from disk, not only a session's old copy. Record
the active path and revision or hash in the project profile. Check the framework
checkout and the agent's actual load path separately from the published source.
On the maintainer's VM, the machine profile records the shared CLAUDE file,
framework checkout and measurement entry point. Another machine supplies its own.
Do not infer a rollout from a dropped lesson candidate or a merged README.

Find the project's existing commands, source boundaries, evidence directory,
review seats, native job interfaces and configured deadlines. Keep the current
mode, review budget, test order and authorization. A changed instruction does
not silently change a frozen review; apply the existing amendment rules.

Identify usage sources and how the installed reader supports them. Resolve them
from this task's actual native session/job identity and project context. The newest
log on a shared VM may belong to another agent. Use explicit native IDs and
project/actor/slice/stage labels. An engine, owner ledger or
verified approval mechanism that is not installed cannot be treated as active.

## Prepare and run work

Batch independent source reads and native launches where the interface supports
it. Keep dependent actions and gates in their existing order. Reuse the project's
commands and retained artifacts; do not build a new script for a capability that
already works. Record source identity and evidence locations before expensive work.

Each reviewer still receives every required brief element, full source/context
access, the freeze and control question, and its own absolute output path. A
verified file pointer can avoid repeated transport. It cannot remove context,
shorten the review or replace completion/model/response/delivery checks. Launch
independent legs against the same freeze and keep their outputs isolated.

Wait through the host's native completion interface within its supported wait
limits. Keep progress updates and independent authorized work. A launcher exit,
file appearing, old output or low CPU alone is not completion or failure. Use
only configured deadlines and cancellation rules; retain interrupted outputs.
Do not blindly retry an operation whose outcome is unknown. Reconcile its native
job/result identity first. No new automatic retry authority is granted.

Close a review round before acting on any finding. Keep every full filing and
its native completion evidence. Use structured result indices to navigate gates
and reviews, then read originals wherever judgment requires them. Gates remain
sequential; this update does not enable parallel gates or a supervisor daemon.

## Measure completed scopes

Follow TOKEN-BUDGET's active native-usage procedure once per completed scope.
The delivered reader and full input/output contract are in [the pilot guide](DFLOW-PILOT.md).
Run it from the framework checkout with its validated interpreter and absolute
paths to the measured project's manifest and evidence. The agent's project
checkout and attribution stay the measured project's, not the framework's.

Use stable saved native logs. Keep a captured prefix explicitly labelled as that
prefix, with its original source, captured range, hashes and limits. Never hide
a torn record, rewrite source data or describe an active session as complete.
Retain exact full inputs and full output in private evidence. A measurement
result is an index into those inputs, not an authenticated owner record.

The reader separates missing fields from zero, merges supported split records,
checks native identities and excludes replayed ancestor calls from new spend.
Cumulative totals check increments. Reasoning is inside output. Record the exact
window, source/tool revisions, known subtotals and coverage gaps. An unsupported
shape, missing runtime/source or nonzero exit is a failed or partial measurement;
record `UNAVAILABLE` and continue independent authorized engineering. Required
quota, review and gate conditions still apply. No metric result waives them.

Token volume, model prices, subscription quota, elapsed time and engineering
quality are separate measures. No fixed cross-provider cache-price schedule or
savings forecast is adopted. A comparison needs an equivalent baseline, relevant
configuration and quality evidence. Missing comparison evidence stays unavailable.

## Finish, hand off and clean up

Link owner requirements, corrections, existing authorization and open decisions
to the retained plan and handoff. Keep the source revisions, full review history,
check evidence, measurements, actual deployment and rollback facts. This update
adds no new owner approval expiry, reclassification or chat stop.

A framework update is delivered only after the published source and the actual
shared instructions/profile are installed and read back. Verify generated inline
copies too. Existing sessions read current disk files at discovery/resume;
the agent must not claim that an old cached context has refreshed itself.

Preserve required full evidence and restore recipes before removing unused,
owned builds/caches/worktrees. Check current use. No evidence-prune period is
adopted. The separate security track is unchanged: same-user hashes and native
message provenance are not authentication, and shared privileged access is not
an independent security boundary.

## What remains separate

The store, executable workflow guards, native Agent attach adapter, gate/review
runners and owner ledger proposed for the larger engine are not delivered by this
instruction update. Their reliability and adapter prerequisites still need proof.
The full archive/quality/second-machine acceptance remains open. Identity
separation, sandbox adoption, fresh sessions, instruction packs and parallel gates
keep their own decisions and evidence requirements. This is an active procedure
using existing capabilities, not a false claim that those components passed.
